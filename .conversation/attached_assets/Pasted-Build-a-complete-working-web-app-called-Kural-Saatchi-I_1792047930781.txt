Build a complete, working web app called "Kural Saatchi (குறள் சாட்சி)". It verifies whether a Tamil quotation really exists in the Tirukkural (1330 couplets) and abstains when it cannot prove a match. Don't ask questions. Build, run and test it.

CORE PRINCIPLE: Verification first, generation last.
- The verdict always comes from a deterministic string-matching pipeline against the source text, never from an LLM.
- No code path may output couplet text that isn't read from the corpus file.
- NOT_FOUND must never return a match object.

TECH STACK
- Python 3.11, FastAPI, Uvicorn, Pydantic, rapidfuzz, scikit-learn, numpy, regex, httpx, pytest.
- Frontend: static index.html + app.js (vanilla JS) + styles.css, served by FastAPI. Tailwind CDN, Chart.js CDN, html2canvas CDN. Google Fonts: Inter, Noto Sans Tamil, Noto Serif Tamil.
- No database; data lives in JSON files in /data.
- Run: uvicorn app.main:app --host 0.0.0.0 --port 8000

CORPUS
- Download https://raw.githubusercontent.com/tk120404/thirukkural/master/thirukkural.json. Inspect the keys and map them flexibly (number, line1, line2, English translation, explanations).
- Fallback: GET https://api-thirukkural.vercel.app/api?num={1..1330}.
- Last resort: use the seed below and show a yellow "DEMO CORPUS" banner.
- Validate at startup: 1330 entries, contiguous numbers, two lines each. Compute a SHA-256 corpus hash and show it in the footer.
- Derive adhikaram_no = ceil(number/10). Paal: Aram 1-380, Porul 381-1080, Inbam 1081-1330. Never invent chapter names.

NORMALIZATION
NFC; remove zero-width chars; keep only the Tamil block (U+0B80-U+0BFF) and whitespace; collapse spaces; produce norm and norm_nospace. Use a grapheme splitter for all diffs: regex.findall(r'[\u0B85-\u0B94\u0B83]|[\u0B95-\u0BB9][\u0BBE-\u0BCD\u0BD7]?|.', s).

VERIFICATION PIPELINE (stop at the first terminal verdict)
0. Preprocess. If < 3 words or < 10 graphemes → TOO_SHORT (abstain).
1. Exact.
   - nospace equality with a couplet → VERIFIED.
   - Word-boundary substring of one couplet with ≥ 3 words → VERIFIED_FRAGMENT.
   - nospace substring with ≥ 12 graphemes → VERIFIED_FRAGMENT with the note "spacing differs".
2. Candidates: TfidfVectorizer(analyzer="char", ngram_range=(2,4)) over norm_nospace, top 10.
3. Rerank with rapidfuzz ratio: full, line1 and line2 scores (and partial_ratio for single lines).
4. Splice: two input lines, each ≥ 0.90 to lines of DIFFERENT couplets → SPLICED (return both references).
5. Decoy: match ≥ 0.90 (or exact) against the decoy corpus → MISATTRIBUTED (work, author, ref).
6. Misquote: best score ≥ 0.80 → MISQUOTED, with the canonical text and a grapheme-level diff (equal/sub/ins/del via difflib).
7. Otherwise NOT_FOUND (abstain) with the "nearest" list (score ≥ 0.45, labeled "NOT a match").
Claim check: if a Kural number is claimed, return OK / WRONG_NUMBER (give the real number) / UNSUPPORTED_CLAIM.
Config thresholds are env-overridable: MISQUOTE_MIN=0.80, SPLICE_LINE_MIN=0.90, DECOY_MIN=0.90.
Each result includes an evidence list and a pipeline trace (stage, ms, detail).

QUOTE FIREWALL (Guarded Chat + AI Guard)
- Live mode (if GEMINI_API_KEY is set, model gemini-2.0-flash via the REST generateContent endpoint): the system prompt forbids the LLM from writing couplet text and says to cite only [[KURAL:n]] tokens. The server replaces each token with the canonical text from the corpus. Any Tamil quote the LLM writes anyway is run through the guard: misquotes are corrected; NOT_FOUND, SPLICED and MISATTRIBUTED quotes are replaced with "⚠ [unverified quote removed]". The Raw column comes from a separate plain prompt asking for the quote.
- Simulator mode (no key): 6 canned scenarios whose guarded output is produced by the REAL pipeline:
  1. an altered 391 ending in "தக்க" → MISQUOTED
  2. "யாதும் ஊரே யாவரும் கேளிர்" credited to Valluvar → MISATTRIBUTED
  3. the fake "தோல்வி என்பது வெற்றிக்கு முதல் படி" → NOT_FOUND
  4. 391 line 1 + 396 line 2 → SPLICED
  5. a correct 616 with the claimed number 618 → WRONG_NUMBER
  6. a correct 322 → VERIFIED

BENCHMARK LAB (seed 42)
Generate real ×200 (with spacing and punctuation noise), corrupted ×200 (1-3 grapheme edits), spliced ×100, fabricated ×200 (≥ 50% of words swapped from other couplets), and the decoy corpus. Report the confusion matrix, per-class accuracy, False-Accept Rate and abstention rate, against a naive baseline ("accept the best fuzzy match ≥ 0.6"). Threshold sliders recompute live. Target: 0% false-accept for fabricated and decoy at default thresholds, with the baseline clearly worse (tune the defaults if needed without weakening the exact-match rules).
